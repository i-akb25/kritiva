# Configure KRITIVA Local AI

This guide enables KRITIVA's optional **2D image to GLB** workflow on your own computer. It does not turn the public Vercel deployment into a free GPU service.

## Read this first

- Run **KRITIVA and the Local Compute Connector on the same computer**. A Vercel server cannot reach `127.0.0.1` on your laptop.
- Stable Fast 3D (SF3D) currently reconstructs a model from **one front image**. The unseen sides are estimates.
- NVIDIA CUDA is the practical option. Apple Silicon MPS is experimental. Intel and AMD use the CPU fallback and can be much slower.
- The model is free only under its own licence. Its gated weights require a Hugging Face account and acceptance of Stability AI's terms.
- Do not commit `.env.local`, access tokens, or Hugging Face credentials.

## 1. Requirements

Install:

- Git
- Node.js 22 or newer
- pnpm 11 or newer: `corepack enable`
- Python 3.10 or 3.11 recommended
- A Hugging Face account

For NVIDIA on Windows, WSL2 with Ubuntu is the most reliable route. Native Windows support in SF3D is experimental and requires Visual Studio 2022 build tools. Apple Silicon requires OpenMP and a compatible PyTorch MPS build.

Official references:

- SF3D installation: <https://github.com/Stability-AI/stable-fast-3d>
- Gated SF3D weights: <https://huggingface.co/stabilityai/stable-fast-3d>
- PyTorch installer: <https://pytorch.org/get-started/locally/>

## 2. Download KRITIVA

```bash
git clone https://github.com/i-akb25/kritiva.git
cd kritiva
corepack enable
pnpm install
```

## 3. Install Stable Fast 3D

Keep SF3D beside KRITIVA or in another directory:

```bash
git clone https://github.com/Stability-AI/stable-fast-3d.git
cd stable-fast-3d
python -m venv .venv
```

Activate the environment.

macOS, Linux, or WSL2:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Install PyTorch first using the command generated by the official PyTorch installer for your operating system and accelerator. Then install SF3D:

```bash
python -m pip install --upgrade pip
python -m pip install --upgrade setuptools==69.5.1 wheel
python -m pip install -r requirements.txt
```

Open the gated model page, accept its terms, create a read-only Hugging Face token, and authenticate locally:

```bash
hf auth login
```

If your Hugging Face installation is older, use `huggingface-cli login` instead. Never put that token in KRITIVA's environment file.

Verify SF3D before connecting it to KRITIVA:

```bash
python run.py demo_files/examples/chair1.png --output-dir output/
```

Do not continue until this creates a `.glb` file. If this command fails, the KRITIVA connector will fail for the same reason.

## 4. Choose the engine

| Computer | `KRITIVA_LOCAL_ENGINE` | What to expect |
| --- | --- | --- |
| NVIDIA RTX | `sf3d-cuda` | Fastest supported SF3D path; about 6 GB VRAM at default settings |
| Apple Silicon | `sf3d-mps` | Experimental; use CPU when MPS is unstable or memory is below 32 GB |
| Intel CPU | `sf3d-cpu` | Works without CUDA, but generation can be slow |
| AMD CPU | `sf3d-cpu` | CPU fallback only; KRITIVA does not claim ROCm support |
| Automatic | `auto` | Selects MPS on Apple Silicon, CUDA when `nvidia-smi` exists, otherwise CPU |

`nvidia-nim` is a separate advanced option. It requires a locally running compatible TRELLIS NIM endpoint and is not automatically installed by KRITIVA.

## 5. Configure KRITIVA

Return to the KRITIVA directory. Copy the example environment file:

macOS, Linux, or WSL2:

```bash
cp .env.example .env.local
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env.local
```

Generate a private connector token:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Put that generated value in `.env.local`:

```dotenv
NEXT_PUBLIC_SITE_URL=http://localhost:3000
KRITIVA_AI_MODE=local-compute
KRITIVA_LOCAL_PROFILE=auto
KRITIVA_LOCAL_CONNECTOR_URL=http://127.0.0.1:8787
KRITIVA_LOCAL_CONNECTOR_TOKEN=paste-the-generated-token-here
```

The token must be identical in the KRITIVA and connector terminals.

## 6. Start the Local Compute Connector

Open a new terminal in `kritiva/connectors/local-rtx-connector` and create its small API environment:

```bash
python -m venv .venv
```

Activate it, then install the connector dependencies:

macOS, Linux, or WSL2:

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Set these values. Replace the paths and token with your real local values.

macOS, Linux, or WSL2:

```bash
export KRITIVA_LOCAL_CONNECTOR_TOKEN="paste-the-same-token-here"
export KRITIVA_LOCAL_ENGINE="auto"
export SF3D_REPO_PATH="/absolute/path/to/stable-fast-3d"
export SF3D_PYTHON="/absolute/path/to/stable-fast-3d/.venv/bin/python"
python -m uvicorn server:app --host 127.0.0.1 --port 8787
```

Windows PowerShell:

```powershell
$env:KRITIVA_LOCAL_CONNECTOR_TOKEN="paste-the-same-token-here"
$env:KRITIVA_LOCAL_ENGINE="auto"
$env:SF3D_REPO_PATH="C:\absolute\path\to\stable-fast-3d"
$env:SF3D_PYTHON="C:\absolute\path\to\stable-fast-3d\.venv\Scripts\python.exe"
python -m uvicorn server:app --host 127.0.0.1 --port 8787
```

Keep this terminal open. The connector binds only to loopback and is not exposed to your network.

## 7. Verify the connector

In another terminal, replace the token and run:

```bash
curl -H "Authorization: Bearer paste-the-same-token-here" http://127.0.0.1:8787/health
```

Expected status:

```json
{
  "status": "ready",
  "engine": "sf3d-cuda",
  "gpu": "your GPU or null",
  "system": "your operating system"
}
```

If the status is `setup-required`, check `SF3D_REPO_PATH`. If you receive `401`, the two connector tokens do not match.

## 8. Start KRITIVA and generate a model

Open another terminal in the KRITIVA repository:

```bash
pnpm dev
```

Then:

1. Open <http://localhost:3000/tools/ai>.
2. Confirm the page says **Provider ready**.
3. Select **2D image to 3D model**.
4. Upload one PNG, JPEG, or WebP front image no larger than 12 MB.
5. Use an isolated object on a plain background for a better result.
6. Tick the local-processing consent box.
7. Select **Reconstruct 3D model** and keep both terminals running.
8. Download the returned `.glb` and inspect it in KRITIVA's 3D Model Lab.

## Troubleshooting

### The hosted website still says “Provider not configured”

That is expected. `kritiva.vercel.app` runs on Vercel and cannot call your computer's loopback connector. Use `http://localhost:3000` for local AI.

### SF3D cannot download the model

Accept the model licence on Hugging Face, authenticate in the SF3D environment, and retry the standalone `run.py` test.

### `ModuleNotFoundError` appears during generation

`SF3D_PYTHON` is pointing to the wrong interpreter. It must point to the Python executable inside the environment where SF3D's dependencies were installed.

### CUDA is not detected

Run this inside the SF3D environment:

```bash
python -c "import torch; print(torch.cuda.is_available(), torch.version.cuda)"
```

If it prints `False`, reinstall the PyTorch build matching your driver and CUDA setup. KRITIVA cannot repair an incompatible CUDA installation.

### Apple Silicon runs out of memory

Switch `KRITIVA_LOCAL_ENGINE` to `sf3d-cpu`. MPS support is experimental and SF3D's maintainers recommend CPU below 32 GB unified memory.

### Intel or AMD processing appears stuck

CPU reconstruction can take substantially longer than CUDA and use considerable memory. Watch the connector terminal for progress. A weak laptop is technically compatible but may not be practical for this workload.

### Stop local AI

Press `Ctrl+C` in the connector terminal and the KRITIVA development terminal. Temporary model-job files are created in an operating-system temporary directory and deleted after each request.
